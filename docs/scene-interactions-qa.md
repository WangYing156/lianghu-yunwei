## 重点回归修复

1. 二维定位不再依赖 2,000,000m 相机高度或累积相对缩放，改由固定米制 Rectangle 求解完整正交视锥。
2. 弹窗坐标每帧更新时不再重建内容 DOM / 图表；关闭、视频调取按钮保持可点击，图表 RAF 在回收时取消。
3. 选中/告警图标独立于普通聚合，并在拾取时优先，避免聚合数字抢走点击。
4. 打开构件或聚合成员检视时收起业务遮罩；详情/列表不再被侧栏拦截。
5. 同一世界剖切平面分别转换到施工/竣工根坐标，进入二维/巡游时暂停、返回恢复，销毁时回收。
6. 道路白色中性乘色保留原始 PBR/贴图和不透明度，结构透视不连带玻璃化道路。

## 数据边界

告警与普通业务点为显式模拟状态，重点监控为仓库示例图片/GIF；无后端实时告警和摄像机授权流，不宣称已接入实时服务。BIM 的几何、构件编号、位置来自真实模型。合并导出的整段灯具/构件不能逐设备定位，未伪造虚假的独立设备。数字应急工况读数与设备状态同样是脚本推演值；真实的是 BIM 几何、双层路面与 16 台竣工风机位置。

## 2026-11-11 补充 · 数字应急 / 孪生工况推演复核

**范围**：当前分支 `arena/b163fd6f-lianghu-yunwei`（基于 `b04c6dbaf12c4bc31ab3161521e3ca39955c28eb`）。本补充不改写 2026-10-22 的 29 项原始结论，而是在「数字应急 → 四维工况推演」改为接管同一个 Cesium 主视图后，复核主视图推演、场景生命周期、模块点位、交付文档和构件数量口径。

### 交付口径

- 四个脚本：火灾疏散、积水排涝、交通事故、日常巡检；全部在**同一个 `TunnelScene` / Cesium 主视图**内运行，不是页内示意视窗、页面联动巡游按钮或头显系统。
- 真实数据：竣工 BIM 几何、上下层路面采样、16 台风机模型与轴向，以及 `scenetree.json` 解析出的 **165 个独立构件**；旧文档 / 脚本中按目录误写的 `138` 已更正。
- 脚本数据：工况读数、设备状态、告警热点、处置阶段均为「工况推演值 · 非实时测点」，不下发设备指令、不接实时 IoT、不接实时视频。边界常量为：`TWIN_DATA_NOTE = '工况读数与设备状态为脚本推演值，非实时测点；BIM 几何、双层路面与风机位置来自真实竣工模型。'`
- 立体分屏是 Cesium 的 Cardboard 双视图，不是 WebXR 头显；二维 / 正交投影下会安全退出立体模式，避免 Cesium 1.146 `Scene.useWebVR` 与 `OrthographicFrustum` 冲突。

### 本轮关键修复

1. `useTwinSimulation.ts` 在 `buildEffects()` 与事故步骤回调中调用 `applyBaselineVentilation()`，保证四类工况都接管 16 台真实风机；火灾工况另有分阶段排烟 / 恢复计划，避免风机覆写被互相清空。
2. `simulationPhysics.ts` / `twinScenarios.ts` 提供水平水面按真实纵坡求交、方向无关的上坡淹没范围、步内进度插值、总时长与步骤感知的第一人称起点；火灾排烟在第 3 步后半段才回落常规通风，复盘阶段设备表与烟气方向一致。
3. 推演生命周期保存并恢复相机、图层、气流、透视、漫游、立体分屏与场景高度；切步暂停、调速、重入 / 从头推演、退出预览、启动失败回滚均已接入 HUD 与页面卡片；普通工具栏在推演期间锁定或安全退出。
4. `useCesiumTunnelMap.ts` 的 `destroy()` 改为先摘除 tileset、`partialFx` 与点击处理器，再清空 `viewer.value` 并销毁 Viewer，消除 `PrimitiveCollection.removeAll()` 对已释放图元的二次销毁；六模块切页不再残留旧拾取回调。
5. `scenePoints.ts` 将六个业务模块的默认分组对齐各页面实际传入的原始点位：数字服务的投诉点位（`monitor`）不再因历史 `structure` 默认分组而全部隐藏；单测、浏览器回归、README / 使用说明 / 思维导图 Markdown、PNG 与 DOCX 的默认分组表同步更新。
6. README、交付文档、功能清单、思维导图 PNG、说明文档 DOCX、QA 与 `scripts/smoke-scene.mjs` 中的真实构件计数统一为 165；未改动 `clusterSymbolUrl(138)`、桩号 / 文件名等无关数字。
